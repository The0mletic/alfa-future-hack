# База знаний аналитических материалов Альфа-хакатона

Текстовая база для анализа новостей с учетом профиля компании. Обработаны **9 PDF, 64 страницы**. Исходники из `applications/analytics` побайтно сверены с архивом [Google Drive](https://drive.google.com/drive/folders/15xZTLF1lZ65p6o5xpNA_fRbxjoV-UlG1) 26.10.2026; SHA-256 сохранены в `source_verification.json`. Все PDF оказались сканами без текстового слоя.

Добавлены только новые папки `applications/knowledge_base` и `scripts/knowledge_base`. Исходные PDF, CSV, профили компаний, Django и существующие скрипты не изменены.

## Что использовать агенту

1. Искать релевантные фрагменты в **[chunks.jsonl](chunks.jsonl)**. Одна строка = один JSON-объект. Передавать модели несколько подходящих фрагментов вместе с новостью и кратким профилем компании.
2. Для чисел использовать **[tables.jsonl](tables.jsonl)**: 21 таблица с именованными столбцами, строками и примечаниями. Ячейки хранятся строками, чтобы сохранить проценты, валюты, знаки, `N/A`, множители `x`, звездочки и обозначения прогнозов. Пустые значения не заменены нулями. В больших таблицах фрагменты повторяют заголовки и примечания.
3. Для контекста открывать документ из **[documents.jsonl](documents.jsonl)** или соседние фрагменты `previous_chunk_id` / `next_chunk_id`.
4. Цитировать `source_pdf` + `page_start` / `page_end`. Страницы нумеруются с 1 по физическому порядку в PDF, а не по напечатанному номеру страницы.
5. Для графиков использовать **[figures.jsonl](figures.jsonl)**. Есть названия, отдельные проверенные описания, ссылки на изображения и OCR-метки с расположением. Шкала оси не является временным рядом. Если вопрос требует точного значения с линии, открыть соответствующее изображение.

Эта база не обучает модель и не подключает ее к Django. Она готова для последующей индексации и retrieval/RAG. Пример локального лексического поиска уже доступен без зависимостей и API-ключей:

```bash
python3 scripts/knowledge_base/search.py 'ключевая ставка стоимость кредита' --top-k 3
python3 scripts/knowledge_base/search.py 'РусГидро EBITDA' --top-k 3
python3 scripts/knowledge_base/search.py 'инфляция потребление' --as-of 2026-08-01
python3 scripts/knowledge_base/search.py 'сталь Северсталь' --include-historical
```

Команды запускаются из корня репозитория. Поиск использует BM25-подобное ранжирование и простую нормализацию русских слов; это пример интеграции, а не семантический поиск. Он не обращается к сети и ничего не записывает.

## Файлы

| Путь | Назначение |
|---|---|
| `documents/*.md` | Отдельный читаемый документ с постраничной структурой, текстом и таблицами |
| `documents.jsonl` | Каталог документов, даты, периоды, темы, хеши и пути |
| `blocks.jsonl` | Все обработанные блоки, включая титулы и дисклеймеры |
| `chunks.jsonl` | Фрагменты для модели; титульные страницы и правовые оговорки исключены из поиска |
| `tables.jsonl` | Структурированные таблицы, сверенные с изображениями |
| `figures.jsonl` | Каталог 96 графических областей; одна область иногда содержит несколько связанных элементов |
| `figures/*.webp` | Читаемые фрагменты исходных изображений: таблицы и графики |
| `layouts/*.txt` | OCR-метки с сохранением горизонтального расположения |
| `ocr/pages.jsonl` | Неизмененный исходный OCR всех 64 страниц с координатами и уверенностью |
| `ocr/regions.jsonl` | Повторный OCR отдельных колонок, таблиц и графиков |
| `source_verification.json` | Результат сверки Google Drive и локальных файлов по SHA-256 |
| `quality_report.json` | Число документов, страниц, фрагментов, статусы качества и ограничения |

## Как читать метаданные

- `published_at`: дата публикации, явно напечатанная в документе; `null`, если точная дата неизвестна. `publication_month` у обзора золота отражает месяц на обложке, а не доказанную дату выхода.
- `data_period`: основной период обзора. Отдельные таблицы и графики охватывают другие даты; использовать также их заголовки и колонки.
- `historical`: пометка обзора стали за 2021 год. Он исключен из примера поиска по умолчанию. Для истории включить `--include-historical`.
- `quality`: `ocr_transcription` для текста, `visually_checked_against_source` для таблиц, `chart_labels_only` для графиков без проверенного описания, `visual_description_checked` для проверенных подписей/описаний.
- `bbox`: координаты блока на исходной странице от 0 до 1, начало в левом верхнем углу. В `ocr/regions.jsonl` координаты строк относятся к изображению блока, в `ocr/pages.jsonl` — к целой странице.
- `contains_forecast_terms`: вспомогательный поиск слов, а не надежный классификатор. `statement_type` явно указывает на смесь фактов, оценок, прогнозов и мнений источника.

Сохранять формулировки «ожидаем», «прогноз», «по нашему мнению» и периоды. Столбцы `П`, `e`, `АБ` могут содержать прогнозы; конкретная расшифровка дана в примечаниях таблиц. Не выдавать прогноз за состоявшееся событие. Различающиеся версии прогнозов не объединены: например, ожидание ставки на конец 2026 года составляет 13,5% в записке от 07.09 и 14,0% в записке от 11.09.

При анализе исторической новости задавать `--as-of YYYY-MM-DD`. Такой поиск исключает документы с более поздней или неизвестной точной датой публикации, включая обзор золота без точного дня. Для обычного поиска без временного среза обзор золота доступен.

## Качество и границы преобразования

Распознавание выполнено локально через Apple Vision (`ru-RU`, `en-US`, accurate). Колонки и графики разделены перед повторным OCR, чтобы не смешивать абзацы с осями. Все страницы проверены на наличие содержимого и структуру; таблицы дополнительно сверены визуально. Обнаруженные пропуски текста исправлены по изображениям с отдельным журналом в `scripts/knowledge_base/text_corrections.json`. Узкие нормализации OCR: `ОФ3` → `ОФЗ`, отдельное `Ць`/`ць` → `ЦБ`. Исходный OCR сохранен без исправлений.

Это не ручная посимвольная вычитка всего корпуса. Возможны остаточные ошибки OCR, особенно в мелких подписях и юридических оговорках; уверенность OCR не гарантирует правильность. Статус проверенной таблицы относится к соответствию изображению, а не к внешней достоверности данных. Арифметические расхождения и неодинаковые версии показателей в источниках сохранены. Полные временные ряды с графических линий не оцифрованы: изображения и расположение OCR-меток доступны для проверки.

Тексты кейса не обновлялись по внешним источникам. Не использовать прошлые цены, ставки и рекомендации как сегодняшние. Правовые оговорки сохранены в полных документах и исходном OCR, но не занимают контекст в поисковой выдаче.

## Проверка и повторная сборка

Без установки библиотек и повторного OCR:

```bash
python3 scripts/knowledge_base/build.py
python3 scripts/knowledge_base/validate.py
```

Сборка детерминированно использует сохраненный OCR, разметку и проверенные таблицы. Проверяет хеши исходных PDF и записывает только файлы базы знаний в этой новой папке. Проверка контролирует охват страниц, ссылки, структуру таблиц, отрицательные значения, отсутствие подмены `N/A` нулем, сохранность разных версий прогноза и работу поиска с ограничением по дате.

Как повторить OCR или добавить новый PDF — см. [инструкцию к скриптам](../../scripts/knowledge_base/README.md).

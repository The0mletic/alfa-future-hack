# Сборка базы знаний из PDF

Скрипты изолированы от существующего приложения. Корень проекта вычисляется относительно расположения скриптов. Никакие исходные PDF, CSV, зависимости Django или профили компаний не перезаписываются.

## Быстрая пересборка

Из корня репозитория:

```bash
python3 scripts/knowledge_base/build.py
python3 scripts/knowledge_base/validate.py
```

Нужен Python 3.10+; для сборки из сохраненного OCR достаточно стандартной библиотеки. Основной выход — `applications/knowledge_base/chunks.jsonl`. Схема и правила использования описаны в `applications/knowledge_base/README.md`.

## Полное повторение OCR

Требуется macOS с Apple Vision, поддерживающим `ru-RU`, и Swift compiler. Данные не передаются в облачный OCR. Для рендеринга нужны `pypdfium2` и `Pillow` из отдельного `requirements.txt`; существующий корневой файл зависимостей не изменять.

1. Проверить хеши исходных PDF и разметку `layout.json`. Разметка привязана к конкретным документам: координаты задаются относительно целой страницы, от левого верхнего угла.
2. Подготовить изображения областей и обновить изображения таблиц/графиков:

   ```bash
   python3 scripts/knowledge_base/prepare.py --work-dir /tmp/alfa-kb-ocr --export-visuals
   ```

3. Скомпилировать и запустить распознавание:

   ```bash
   swiftc -module-cache-path /tmp/alfa-kb-swift-cache scripts/knowledge_base/ocr.swift -o /tmp/alfa-kb-ocr-tool
   /tmp/alfa-kb-ocr-tool /tmp/alfa-kb-ocr/regions.json /tmp/alfa-kb-ocr/recognized.jsonl
   ```

   Файл результата должен быть новым: OCR отказывается перезаписывать существующий. При запуске в песочнице macOS Vision может требовать разрешение на локальное выполнение вне песочницы. Время и точность могут отличаться между версиями macOS/Vision. Скрипт завершается ошибкой при пустом результате; не продолжать сборку с недостающими областями.

4. Сверить новый OCR с исходниками. Проверить границы колонок, обрезанные строки, минусы, даты, проценты, валюты и сноски. Только после проверки заменить **новый для проекта** файл `applications/knowledge_base/ocr/regions.jsonl` результатом. `ocr/pages.jsonl` хранит первоначальный постраничный OCR для аудита, пересборка его не меняет.
5. Проверить `verified_tables.json` и журнал исправлений `text_corrections.json`: это данные, сверенные с изображениями. Если OCR изменился, `build.py` намеренно остановится при несовпадении исправляемой строки; нужно сверить и обновить исправление, а не применять его вслепую.
6. Выполнить `build.py` и `validate.py`.

`prepare.py` и `build.py` останавливаются, если хеш исходника изменился. При добавлении новой версии сначала нужно обновить каталог, хеши после сверки, разметку и проверки охвата; автоматически переносить старые координаты и исправления на новый файл нельзя.

## Состав

- `layout.json`: каталог, даты, темы, последовательность и границы блоков; проверенные описания отдельных графиков.
- `verified_tables.json`: 21 проверенная таблица со всеми колонками, строками и примечаниями. Значения остаются строками, пустые ячейки не заполняются нулями.
- `text_corrections.json`: адресные исправления пропусков/ошибок OCR с обоснованием. Оригинальные строки остаются в OCR-кэше.
- `prepare.py`: рендеринг PDF и выделение областей для OCR.
- `ocr.swift`: локальное распознавание изображений; координаты и уверенность сохраняются.
- `build.py`: Markdown, каталог, блоки, фрагменты, таблицы, графики и отчет качества.
- `search.py`: пример поиска без модели и API-ключей; в приложение не встроен.
- `validate.py`: проверка целостности и ключевых сценариев поиска.

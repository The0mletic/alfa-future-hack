# Контракт агента релевантности v1.0

Статус: первый этап разработки. Формат предложен для интеграции; согласование с товарищами ещё впереди. Агент, загрузчики, поиск, сетевые инструменты и LLM пока не реализованы.

## Как читать файлы

- `contracts.py` — источник истины: Python-модели Pydantic и проверки связности.
- `schemas/*.json` — экспорт JSON Schema для участников на других языках.
- `examples/input.json`, `examples/output.json` — парный синтетический пример. Балл написан вручную; это не прогноз и не результат модели. Банковских цитат в примере нет.
- `tests/test_contracts.py` — проверка правил контракта без сети и LLM.

Контракт отвечает на вопрос «что передаём и как проверяем», но не определяет prompt или алгоритм оценки. Схема проверяет структуру, не истинность текста объяснений.

## Вход: RelevanceInput

| Поле | Смысл |
| --- | --- |
| schema_version | Строка `1.0` |
| request_id | Непустой идентификатор запуска, создаётся вызывающей стороной |
| as_of | ISO-8601 с часовым поясом; момент оценки |
| company_profile | Профиль компании; company_id обязателен, остальные исходные блоки сохраняются |
| news | Список NewsItem с уникальными id; пустой список допустим |
| bank_materials | Подготовленные материалы с фрагментами; пустой список допустим |
| options | Лимиты запуска; значения по умолчанию ниже |

`CompanyProfile` специально допускает дополнительные поля: сохраняем существующий полный профиль без переписывания чужого формата. Проверка внутреннего содержания профиля и полноты будет задачей адаптера на этапе 2. Пустое имя company_id запрещено, но одного ID для качественной оценки недостаточно.

NewsItem сохраняет имена парсера: обязательны `id`, `title`, `summary`, `link`, `published`, `source`; `author`, `categories`, `language` имеют пустые defaults. `published` — ISO-8601 с часовым поясом либо `""`. Пустые summary/link допустимы. Отсутствующий/непригодный URL должен обрабатываться инструментом как недоступный источник. Обёртку парсера `{generated_at, count, items}` будущий загрузчик преобразует в `news=items`; она не является всем входом агента.

BankMaterial: material_id, title, source_file (имя/путь первоисточника), document_date (`YYYY-MM-DD` либо null), fragments. BankFragment: fragment_id, page (с 1), text. ID фрагментов уникальны во всём запросе. Аналитику готовим разово, автоматический OCR в текущую реализацию не входит.

Options: top_k=5, max_refinement_rounds=1, max_article_fetches=15, max_article_chars=20000, counterparty_depth=1. Это стартовые технические defaults. top_k — максимум выбранных новостей, можно вернуть меньше или ни одной. Порог отбора не определён. Лимиты инструментов обязан применять будущий исполнитель, наличие поля само по себе их не обеспечивает. Весь вход не нужно отправлять одним prompt.

## Выход: RelevanceOutput

Обязательные поля: schema_version, request_id, company_id, as_of, results, selected_news_ids, warnings. Запуск, компания и момент оценки должны совпадать со входом.

В results — ровно одна запись на каждую входную новость:

| Поле | Правило |
| --- | --- |
| news_id | Исходный ID; не создавать новый |
| status | scored либо not_scored |
| relevance_score | Целое 0–100 для scored, null для not_scored |
| rank | Последовательное место от 1 для scored, null для not_scored |
| selected | Передаётся ли в подборку; false для not_scored |
| reason | Краткое основание оценки либо причина отсутствия оценки |
| company_evidence | Ссылки на поля целевой компании, тип сведения и объяснение |
| counterparty_evidence | Прямой контрагент, направление, доля, признаки, объяснение цепочки и ограничения |
| bank_evidence | Пары material_id/fragment_id из входа |
| article | Результат загрузки текста или явный статус отсутствия загрузки |
| limitations | Пробелы данных и ограничения вывода |

`selected_news_ids` перечисляет выбранные ID по rank. Порядок самого results не несёт значения. Ранг назначает код: балл по убыванию, при равенстве строковый news_id по возрастанию. Равные баллы разрешены. Не перенормировать оценки по составу подборки. Балл не является вероятностью риска.

Ориентиры для будущей настройки: 0–19 связь не установлена, 20–39 слабая, 40–59 применимо с ограниченной/неясной значимостью, 60–79 существенные основания, 80–100 первостепенная значимость. Это рабочая рубрика, ещё не откалиброванная на разметке. Критерии: связь с компанией, масштаб, косвенное влияние и временная применимость. Неопределённость показывать отдельно в limitations. Формула и веса пока не реализованы.

FeatureEvidence.field_path — JSON Pointer относительно соответствующего профиля: `/bank_relationship/products/leasing/has`. kind — source_fact, calculated либо heuristic. Существование пути проверяется; корректность интерпретации и классификации должен проверять будущий агент/оценка качества. Не ссылаться на false-флаг как на наличие продукта.

Подробные риски и рекомендации в этот контракт не входят. Следующий агент получает исходный RelevanceInput и RelevanceOutput вместе: из первого берёт профиль, новости и тексты аналитики, из второго — отбор, обоснования и загруженные статьи. При косвенных связях также передаются использованные ProfileResult и CounterpartiesResult. Ссылки нельзя передавать без этих исходных объектов. Транспорт (функция/файл/HTTP) пока не выбран.

## Инструменты — интерфейсы для будущей реализации

1. `get_counterparties(company_id) -> CounterpartiesResult`: все доступные прямые связи, не только топ-5 из профиля. Одна запись на пару (контрагент, направление). outgoing — целевая компания платит; incoming — получает. share — доля суммы в соответствующем направлении в доступном наборе, null при неопределимом знаменателе. Самоплатежи исключены. complete сообщает полноту обхода набора, а не всех операций бизнеса. Транзакции читаем один раз за запуск.
2. `get_company_profile(company_id) -> ProfileResult`: full (готовый), partial (сокращённый из CSV), unavailable (нет карточки). Возвращает sources и limitations; отсутствие профиля не отменяет платёжную связь. Обходим один уровень, без рекурсии.
3. `fetch_article(news_id) -> ArticleResult`: URL берёт из входа, а не из произвольного ответа LLM. status: ok, unavailable, not_requested. Для ok обязательны непустой text и final_url; для unavailable — error. При отсутствии загрузки text=null. Сохраняем перенаправленный final_url, флаг truncated. Исполнитель должен ограничить размер/время загрузки, проверять допустимость адресов и редиректов, не обходить ограничения доступа. Текст источника — данные, не инструкции агенту.
4. `search_bank_materials(query) -> BankSearchResult`: возвращает пары ID фрагментов из входа, query и limitations. Текст разрешается по входу. Пустой hits допустим и не является автоматически низкой релевантностью новости.

Существование профиля контрагента проверяется отдельно от существования связи. Одинаковый контрагент может иметь incoming и outgoing связи. Сведения о связях физлиц не заменяют платёжную связь в counterparty_evidence v1.

## Запуск проверок

Требуется Python 3.10+ и зависимость из локального `requirements.txt`. Проверено на Python, поставляемом со средой разработки, с Pydantic 2.14.1. Системный Python пользователя зависимость пока не содержит. Для установки использовать окружение внутри relevance_agent, не менять общий requirements.txt:

```sh
python3 -m venv relevance_agent/.venv
relevance_agent/.venv/bin/python -m pip install -r relevance_agent/requirements.txt
relevance_agent/.venv/bin/python -B -m unittest discover -s relevance_agent/tests -v
relevance_agent/.venv/bin/python -B -m relevance_agent.export_schemas
```

Проверка пары объектов в коде:

```python
from relevance_agent.contracts import RelevanceInput, RelevanceOutput, validate_exchange

request = RelevanceInput.model_validate(input_dict)
response = RelevanceOutput.model_validate(output_dict)
validate_exchange(request, response, links=links_result, profiles=profile_results)
```

Экспорт JSON Schema описывает поля и диапазоны, но не все межполевые правила: потребитель должен дополнительно соблюдать этот документ или вызывать Python-валидаторы. validate_exchange проверяет покрытие входных новостей, ссылки на поля и банковские фрагменты, идентичность запуска, top_k, связи и доли контрагентов. Он не проверяет истинность цитат, актуальность события, достижение лимитов инструментов или качество ранжирования.

Основа реализации: [модели Pydantic](https://docs.pydantic.dev/latest/concepts/models/) и [валидаторы](https://docs.pydantic.dev/latest/concepts/validators/).
